At a glance

Problem

Giving an AI your whole wallet is like handing a robot the house keys. One bad prompt can drain everything.

Solution

Separate AI jar + session hall pass + policy teacher + never-guess contacts. If unsure, Pay3 says no.

Humans

Freighter login, fund jar, contacts, session permissions, approvals, revoke.

Agents

MCP tools: balance, transfer, history, swap quote / execute (opt-in).

Request lifecycle

Prove it’s you

Freighter signs a challenge message. Primary key never leaves the wallet.

Link & fund the jar

Pay3 creates an allocation account (or Zipper C for canary). You send only allowance money.

Create AI session

Hall pass with expiry, permissions, encrypted session material.

AI calls MCP

transfer / balance / swap… Bearer token authenticates the session.

Policy → execute

Resolve recipient → AUTO / APPROVAL / REJECT → transaction engine → Stellar.

Security house rules

RuleWhy
Never store primary Freighter keyMain piggy bank stays yours
Never expose session secrets to AI / UIModels and browsers are hostile
Never guess ambiguous recipientsWrong Alex = real loss
No financial auto-retryInsufficient funds / policy / expiry stay dead
Sessions expire + revokeHall passes are temporary
Idempotent transfersRetries don’t double-pay
